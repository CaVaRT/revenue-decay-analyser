# Revenue Decay Analyser Manual

This is the full technical manual for the revenue decay analyser app.

## 1. What The Tool Does

The app identifies pages that are underperforming in organic search by combining:
- GA4 organic sessions and revenue
- GSC organic clicks and impressions
- page-level trend + seasonality-adjusted decay scoring
- automated chart pack and PPTX report

Primary goal:
- find pages losing **revenue and clicks** (not clicks-only)
- prioritize which pages need investigation

## 2. End-to-End Flow

One-command monthly runner:
- script: `scripts/run_revenue_decay_monthly_run.py`
- pipeline: `src/pipelines/revenue_decay_monthly_run.py`

Stages:
1. Pull month-level API data (incremental chunk)
2. Recombine historical chunk store into one model panel
3. Build model input table
4. Score page decay
5. Generate charts + PPTX

## 3. Data Sources and API Logic

### GA4 Extract

Pipeline:
- `src/pipelines/ga4_organic_seo_extract.py`

Auth:
- OAuth or service account

GA4 dimensions used:
- `date`
- page dimension (`landingPagePlusQueryString` by default)

GA4 metrics used:
- `sessions`
- `totalRevenue`

GA4 filters used:
- `sessionDefaultChannelGroup == "Organic Search"`
- optional `country == <your target country>` (or no country filter)

Output:
- daily: `seo_organic_page_daily.csv`
- monthly: `seo_organic_page_monthly.csv`

### GSC Extract

Pipeline:
- `src/pipelines/gsc_organic_page_extract.py`

Auth:
- service account

GSC request dimensions:
- page-level request: `date`, `page`
- property totals request: `date`

GSC metrics captured:
- clicks
- impressions

GSC filters used:
- search type: `web`
- optional country filter (3-letter code), or no country filter

Outputs:
- `gsc_organic_page_daily.csv`
- `gsc_organic_page_monthly.csv`
- `property_totals_daily.csv`
- `summary.json` with coverage diagnostics

## 4. Historical Chunk Strategy

Pipeline:
- `src/pipelines/revenue_decay_chunked_pull.py`

Why:
- API pulls can fail on long windows
- GSC retention is limited
- monthly incremental fetches are safer

What it does:
- stores per-window chunks in:
  - `data/interim/revenue_decay_radar_chunks/<start>_to_<end>/...`
- supports `--resume` to skip existing chunks
- supports combining **all existing chunks** to rebuild a full historical panel

## 5. Model Input Build

Pipeline:
- `src/pipelines/revenue_decay_model_input.py`

Builds monthly page table with columns including:
- `page`
- `month`
- `revenue`
- `clicks`
- `sessions`
- `impressions`
- `page_type`
- coverage flags: `has_ga4_data`, `has_gsc_data`

Join logic:
- outer join on `month + page_path`
- path normalization on both GA4 and GSC before join

Page type:
- inferred from URL rules (beds, mattresses, products, content, etc.)
- optional manual mapping CSV can override

## 6. Normalization and Trend Calculations

Pipeline:
- `src/pipelines/revenue_decay_scoring.py`

### Seasonality factors

Computed by:
- `page_type x month_of_year`

Separate factors:
- `revenue_seasonality_factor`
- `clicks_seasonality_factor`

Adjusted signals:
- `rev_adj = log1p(revenue / revenue_seasonality_factor)`
- `clicks_adj = log1p(clicks / clicks_seasonality_factor)`

### Trend slopes

Per page, over all available months in analysis window:
- `slope_rev` from `rev_adj`
- `slope_clicks` from `clicks_adj`

Method:
- Theil-Sen robust slope
- fallback to `np.polyfit` if needed

### YoY signals

Latest month vs same month previous year:
- `revenue_yoy_delta`
- `clicks_yoy_delta`

These are diagnostic signals, not the sole score driver.

## 7. Scoring Logic

Base decay components:
- `rev_decay_raw = max(0, -slope_rev)`
- `click_decay_raw = max(0, -slope_clicks)`
- rank-normalized to 0..1

Base score:
- `score_base = 0.65 * rev_decay + 0.35 * click_decay`

Confidence factor combines:
- history depth
- GA4 coverage
- GSC coverage
- volume factor (revenue/click scale)
- optional global GSC coverage ratio

Final score:
- `decay_score = score_base * confidence_factor * 100`

Severity bands:
- Critical / High / Medium / Low / Monitor

Key boolean flags:
- `losing_revenue_and_clicks` (both slopes < 0)
- `latest_yoy_both_negative`

## 8. Chart Pack and PPTX

Pipeline:
- `src/pipelines/revenue_decay_chart_pack.py`

Outputs include:
- top risk pages overall
- top risk pages by page type
- risk/severity distributions
- trend panels for high-value at-risk pages
- click-vs-revenue trend correlation scatter
- trend quadrants summary and exports

PPTX:
- generated by `--export-pptx`
- title-safe layout logic avoids overlap with titles
- images keep aspect ratio and stay inside slide bounds
- tables are bounded and title-safe

Current deck intentionally excludes Lumar slides.

## 9. One-Command Monthly Run

Command:

```powershell
venv\Scripts\python.exe scripts\run_revenue_decay_monthly_run.py --history-start-date 2024-10-01
```

Behavior:
- defaults to last completed month
- pulls target month if missing
- recombines full local chunk history from `history-start-date`
- reruns scoring + chart pack + PPTX

## 11. Lumar Integration Status

Current status:
- Lumar is available as optional diagnostics export/chart input
- Lumar is **not** included in final decay score weighting

This matches the current project decision:
- score from revenue + click dynamics first
- use Lumar later for root-cause diagnostics

## 12. Operational Notes

- Keep country filters aligned between GA4 and GSC runs.
- Keep historical start aligned with GA4 reliability period for apples-to-apples comparisons.
- Use chunked pulls with resume to avoid long-run failures.
- Monitor GSC page vs property coverage in summary diagnostics.
